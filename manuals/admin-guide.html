Start here

If you're taking over the Instructor Portal, read this section first. Nothing in the portal needs daily attention: it runs on its own. Your first job is to make sure you can get into every account that holds a part of it.

Your first day

  1. Get access to the accounts that hold the system (see Inventory): the Cloudflare account, the GitHub organization, the Power Automate flow, the Zoom app, and the CLEAR expense system. A CLEAR Microsoft 365 administrator can reset access to anything tied to a CLEAR email address.
  2. Add yourself as a portal administrator: follow Make someone an administrator.
  3. Check the system is healthy: open the staff dashboard Overview. The Zoom links card shows when the daily check last ran (it should be this morning). Open Activity to see recent work.
  4. Read Architecture and How access works. Those two sections explain almost every question that will come up.
  5. Find the secrets. Secret values can't be read back out of Cloudflare. If CLEAR's password manager doesn't have them, you'll create new ones when needed. Every secret can be replaced, and Settings and secrets explains how.

The most important things to know

  • The code lives in GitHub; the data lives in Cloudflare. Editing a file in GitHub publishes it to the site within a minute or two. The data (programs, answers, selections, schedule, reports) is stored in Cloudflare KV and is not in GitHub.
  • Two layers of permission: Cloudflare Access decides who can open the site at all; the portal's own lists decide what they can do once in. Adding or removing a person usually means changing both (see How access works).
  • A changed setting needs a redeploy: after changing any setting in Cloudflare Pages, choose Retry deployment, or the change won't take effect.
  • Every bad change can be undone: any earlier version of the site can be restored in two clicks (Roll back a deployment).
Keep a copy of this guide outside the portal. This guide is hosted inside the portal, so if the portal is down you can't open it. Save a PDF copy (print, then Save as PDF) in CLEAR's shared documents and update it when the system changes.

Architecture

The portal is a small website with a built-in back end, hosted entirely on Cloudflare, with three outside services connected to it.

GitHub repository

Holds all the code: the web pages and the API. Saving a change here starts a new deployment automatically.

→ deploys to Cloudflare Pages

Cloudflare Pages

Hosts the website and runs the API (a "Pages Function", functions/api/[[path]].js) that every page talks to.

↔ reads and writes Cloudflare KV

Cloudflare KV

The database: programs, instructor answers, selections, the roster, the shared schedule, reports and the activity log.

Cloudflare Access (Zero Trust)

Sits in front of the whole site. Nobody reaches any page or the API without signing in with a one-time code sent to an approved email address. Staff pages have a second, stricter Access application.

Daily Worker

instructor-availability-cron runs every morning at 14:00 UTC and asks the portal to send reminders and check Zoom.

→ portal API, through Access with a service token

Power Automate flow

Sends every email the portal produces, from the clearlearning@clearhq.org shared mailbox.

← portal API posts each email to it

Zoom app

A read-only Server-to-Server OAuth app. The portal reads meetings TalentLMS created and matches their links to sessions.

← portal API reads meetings

CLEAR expense system

The clear-lms-proxy Worker, its Power Automate flows and the SharePoint list behind the expense admin. Instructor expense and hours reports are submitted to it through the portal.

← portal API reads the instructor's record and status; submits reports

SurveyMonkey proxy Worker

A separate Worker, owned outside this project, that the evaluation report tool uses to read survey responses.

← evaluation report page, in the browser

Instructor Staffing Dashboard

A separate tool in its own repository. The portal links to it for each instructor's teaching history and evaluations.

DNS (clearhq.org)

Managed by CLEAR's IT provider, outside Cloudflare. A CNAME record points the custom domain at the Pages site.

How a request flows

  1. Someone opens the portal. Cloudflare Access checks they've signed in with an approved email; if not, it shows the one-time code screen.
  2. The page loads and calls the API. The API checks the Access sign-in token again, then works out the person's role from the portal's own lists (administrator, staff or instructor).
  3. The API reads or writes KV and returns the result. For emails it posts to Power Automate; for Zoom links it calls Zoom; for expense reports it calls the CLEAR expense system.
Why two checks? Access keeps strangers out entirely. The API's own check decides what a signed-in person may do, so even if an Access setting were wrong, an instructor still couldn't use staff features.

Nothing else stores portal data. Zoom, TalentLMS and Novi are only read from or used alongside it. Expense reports are stored by the CLEAR expense system, not the portal.

Profiles and the roster

The roster (Instructors tab) is staff-managed: its Last, First name is what evaluation reports and expense reports match on, and its emails are the sign-in addresses. Instructors' profiles are separate and never change the roster. When a profile's name or contact email differs, the Instructors tab flags it for staff to decide.

Procedures

Open a procedure to see its steps.

People and access

Add an instructor
  1. Staff dashboard → Instructors: add the instructor (name as Last, First) and every email they may sign in with. Save.
  2. On Teaching approvals, tick the programs they're approved to teach. Save approvals.
  3. Zero Trust → Access → Groups → CLEAR Instructors → Edit: add their email(s) to the Emails rule. Save.
  4. Ask them to sign in. If they can't, see Troubleshooting.
Remove an instructor
  1. Staff dashboard → Instructors: untick Active (keeps their history) and save.
  2. Remove their email(s) from the CLEAR Instructors Access group.
  3. Check any upcoming confirmed selections on the Selection tab and reassign them.
Add or remove a staff member
  1. An administrator opens the staff dashboard → Staff, adds or removes the person's name and email, and saves.
  2. Zero Trust → Access → Groups → CLEAR Learning Staff: add or remove their email. Save.
  3. When removing someone, also remove them from the Cloudflare account, GitHub organization and Power Automate flow if they had access.
Make someone an administrator
  1. Add them as staff (procedure above).
  2. Cloudflare → Workers & Pages → clear-instructors → Settings → Variables and Secrets: edit ADMIN_EMAILS and add their email, separated from the others by a comma.
  3. Deployments → newest deployment → Retry deployment.
Let the daily Worker past Access (service token)

The Worker signs in with a service token named instructor-availability-cron, allowed by a Service Auth policy on the Instructor Portal application. If the token expires or is deleted, reminders and the daily Zoom check stop.

  1. Zero Trust → Access → Service credentials → Service Tokens → Create Service Token. Copy the Client ID and Client Secret (the secret is shown once).
  2. Instructor Portal application → Policies: make sure a Service Auth policy includes this token.
  3. Worker instructor-availability-cron → Settings → Variables and Secrets: update CF_ACCESS_CLIENT_ID and CF_ACCESS_CLIENT_SECRET. Deploy.
  4. Test with the dry run (see Check the daily Worker), then delete the old token.

Code and deployments

Change a page or the API
  1. In GitHub, open the repository and the file, then choose the pencil icon to edit (or paste in a new version).
  2. Choose Commit changes, committing directly to the main branch.
  3. Cloudflare deploys automatically. Watch Workers & Pages → clear-instructors → Deployments: the newest one should say Success within a minute or two.
  4. Open the page and press Ctrl+F5 to load the new version.
If a page goes blank after an edit, press F12, open the Console, and read the red error and its line number. The most common cause is an apostrophe inside text that's wrapped in single quotes; write it as \' or use a curly apostrophe (’).
Roll back a deployment
  1. Workers & Pages → clear-instructors → Deployments.
  2. Find the last deployment that worked, open its menu (⋯), and choose Rollback to this deployment.
  3. The site switches back immediately. Data isn't affected. Then fix the file in GitHub; the next commit becomes the live version.
Add a new staff-only page
  1. Add the HTML file to the repository root and commit.
  2. Add its path (the file name without .html) to the Instructor Portal – Staff Access application, for every hostname.
  3. Link to it from the staff dashboard if needed.

Settings and secrets

Change a setting
  1. Workers & Pages → clear-instructors → Settings → Variables and Secrets. Edit the value and save.
  2. Deployments → newest → Retry deployment. Settings only take effect on a new deployment.
Replace CRON_SECRET
  1. Make a new random string of about 40 letters and numbers. Save it in the password manager.
  2. Set it as CRON_SECRET on the Pages project, then Retry deployment.
  3. Set the same value as CRON_SECRET on the Worker, then Deploy.
  4. Run the dry run to confirm.
Replace the Zoom secret
  1. marketplace.zoom.us → Manage → the "CLEAR Instructor Portal" app → App Credentials → regenerate the Client Secret.
  2. Update ZOOM_CLIENT_SECRET on the Pages project, then Retry deployment.
  3. Staff dashboard → Overview → Find Zoom links now to confirm.

Email, Zoom and reminders

Check the daily Worker
  1. Open the Worker's address with your CRON_SECRET: https://instructor-availability-cron.<account>.workers.dev/?key=CRON_SECRET&dry=1. Nothing is sent.
  2. You should see today's date, which programs reach a reminder day, and a Zoom summary. "Access did not accept the service token" means the token or its policy needs fixing.
  3. The Worker's Logs tab shows each morning's run.
Fix or rebuild the email flow

The flow receives each email from the portal and sends it from the shared mailbox. It needs a Power Automate licence that includes premium features, because the HTTP trigger is premium.

  1. make.powerautomate.com → My flows → "Instructor Portal – Email" → 28-day run history. Open a failed run to see which step failed and why.
  2. To rebuild it: create an Instant cloud flow with the trigger When an HTTP request is received (Who can trigger: Anyone). Paste this schema: {"type":"object","properties":{"to":{"type":"string"},"bcc":{"type":"string"},"replyTo":{"type":"string"},"subject":{"type":"string"},"html":{"type":"string"}}}
  3. Add the action Send an email from a shared mailbox (V2): Original Mailbox Address clearlearning@clearhq.org; To = to; Subject = subject; Body = html; BCC = bcc; Reply To = replyTo.
  4. Save, copy the trigger's HTTP URL into NOTIFY_FLOW_URL, then Retry deployment.
  5. The flow owner needs Send As permission on the shared mailbox (Exchange admin center → Recipients → Mailboxes → clearlearning → Delegation → Send as).
Add a co-owner to the flow (open the flow → Edit under Co-owners) so it doesn't depend on one person's account.
Fix the Zoom connection
  1. marketplace.zoom.us, signed in with the Zoom admin account → Manage → "CLEAR Instructor Portal". Make sure it's activated and has the scope meeting:read:list_meetings:admin.
  2. Check ZOOM_ACCOUNT_ID, ZOOM_CLIENT_ID and ZOOM_CLIENT_SECRET match the app's App Credentials.
  3. If TalentLMS now creates meetings under a different Zoom user, set ZOOM_USER to that address.
Fix the expense connection

The portal reads each instructor's own entry from the expense system's instructor list, adds their pay rate from its configuration, and submits reports to /expense/volunteer-submit. Status comes from /expense/getall.

  1. If the expense buttons don't appear: check EXPENSE_WORKER_URL is set, then Retry deployment.
  2. If an instructor's name, rate or details don't fill in: in the expense admin's instructor list, make sure their email matches the one on the Instructors tab.
  3. If submitting fails with "The expense system didn't accept the report": check the clear-lms-proxy Worker and its submission flow in Power Automate (run history).
  4. If status never changes from Submitted: check EXPENSE_TOKEN matches the expense admin's token, and that the expense admin can load reports.
Keep the public instructor list closed. The expense Worker's /expense/instructors route used to list every instructor's address and pay tier without signing in. The portal doesn't need it once EXPENSE_TOKEN is set; leave it removed or protected.
An instructor's name or sign-in email changes
  1. Instructors tab: update their roster name (Last, First) and add the new email to their emails. Save.
  2. Add the new email to the CLEAR Instructors Access group; remove the old one once they've signed in with the new one.
  3. Update their entry in the expense admin's instructor list to match, so expense reports keep their rate.

Backups and data

Back up the data
  1. Schedule: Program Scheduler → Facilitators and days off → Download backup.
  2. Answers: staff dashboard → Responses → Export all open programs (a spreadsheet in the coordinator's original layout).
  3. Selections: Selection → Export selections.
  4. Profiles: Instructors → Export profiles. Headshots aren't included; download any you need from each profile.
  5. Store the files in CLEAR's shared documents. Cloudflare keeps the live data safely; these copies protect against accidental deletion.
Restore the schedule
  1. Program Scheduler → Facilitators and days off → Restore from backup, then choose the file.
  2. This replaces the shared schedule for everyone. Published programs in the portal aren't changed until you publish again.

Domain

Switch to (or change) the custom domain
  1. Pages project → Custom domains → Set up a custom domain, and enter the new address first.
  2. Ask CLEAR's IT provider to add a CNAME record: Name instructors, Target clear-instructors.pages.dev.
  3. When the domain shows Active, add it to both Access applications (all staff paths on the Staff application).
  4. Update PORTAL_URL on the Pages project (Retry deployment) and on the Worker (Deploy).
  5. Test signing in as an instructor and as staff in a private browser window.

Recovery

The whole site is down

  1. Check cloudflarestatus.com for a Cloudflare outage. If there is one, wait.
  2. Check the newest deployment. If it failed or broke the site, roll back.
  3. Check the KV binding (IA_KV) and settings are still in place.

Data was deleted or changed by mistake

  • An instructor's answers: re-enter the correct answer on the Responses tab (it's recorded as a staff entry). Earlier versions are stored with each instructor's record in KV (resp:<instructor id>, under history) if you need to look one up.
  • Selections: re-enter them on the Selection tab from your last Export selections file. Earlier versions are also stored in KV (assign:<program id>, under history).
  • The schedule: restore the last scheduler backup.
  • A deleted program: republish the cohort from the Program Scheduler to recreate it. Instructors' earlier answers stay in their records but don't reattach to the new program, so they would need to answer again. To avoid this, use Archived rather than deleting programs.

Rebuilding from scratch

If the Cloudflare project were lost, the code is safe in GitHub. You would recreate the Pages project from the repository, create a KV namespace and bind it as IA_KV, recreate both Access applications and groups, re-enter every setting from Settings and secrets, and recreate the Worker with its cron trigger. Data not covered by backups would be lost, which is why monthly backups matter.

WorkerA small program that runs on Cloudflare. The daily Worker runs on a schedule (a "cron trigger").
Cloudflare Access / Zero TrustCloudflare's sign-in protection. It decides who can open the site.
Access applicationA set of addresses Access protects, with the rules (policies) for who may enter.
Access groupA named list of emails used in policies.
AUD tagAn application's unique ID. The API uses it to confirm a sign-in came from the right application.
Service tokenA sign-in for a program rather than a person, used by the daily Worker.
One-time PINSign-in with a code sent by email; there are no passwords.
DeploymentOne published version of the site. Earlier deployments can be restored.
Power Automate HTTP triggerA web address that starts a flow when the portal sends it an email to deliver.
Server-to-Server OAuth appA Zoom app that lets the portal read meetings without a person signing in.
CNAME recordA DNS entry that points a web address (like instructors.clearhq.org) at another (the pages.dev address).
